# C. ระบบจัดการหลักสูตร

## C1. เปิดระบบ

**หัวสไลด์:** ระบบหลักสูตรเป็นต้นทางของข้อมูล รายวิชาและครูผู้สอนกรอกที่นี่ครั้งเดียว

**บนสไลด์**
- ผู้ใช้: ครูฝ่ายวิชาการจัดการ · ครูผู้สอนดูอย่างเดียว
- แถบเฟส 4 เฟส

```
1 จัดการกลุ่มสาระและรายวิชา → 2 สร้างหลักสูตรและแผนการเรียน → 3 กำหนดครูผู้สอน → 4 ประกาศใช้
        UC-2                          UC-3                         UC-3              UC-3
```

- ใต้แต่ละเฟส 1 บรรทัด
  1. หน่วยกิต ชั่วโมง โครงสร้างคะแนนตั้งต้น ตัวชี้วัด
  2. สร้างใหม่หรือคัดลอกหลักสูตรเดิม เพิ่มแผน ห้อง และรายวิชาตามภาค
  3. เลือกครูเอง (มีครูร่วมสอนได้) หรือให้ระบบเลือกครูในกลุ่มสาระที่ภาระสอนน้อย
  4. ตรวจความครบ แล้วเปิดใช้

**กล่องจุดเด่น** · แก้ปัญหาข้อ 1, 2, 3: กรอกรายวิชาและครูผู้สอนครั้งเดียว แล้วระบบตารางสอนกับระบบคะแนนดึงไปใช้ต่อ · ดูและแก้หลักสูตรได้ในหน้าเดียว ไม่ต้องไล่ 4 ชั้น

**ภาพ:** หน้าจอ `ครูวิชาการ/หลักสูตร/จัดการหลักสูตร`

**พูด:** ข้อมูลที่กรอกที่นี่ ระบบตารางสอนกับระบบคะแนนดึงไปใช้ต่อ ครูไม่ต้องกรอกซ้ำ · โครงสร้างคะแนนตั้งต้นของรายวิชาจะถูกคัดลอกไปเป็นจุดเริ่มของครูในระบบคะแนน

## C2. ประกาศใช้หลักสูตร

**หัวสไลด์:** หนึ่งระดับชั้นใช้ได้ทีละหลักสูตร ประกาศฉบับใหม่แล้วฉบับเดิมปิดอัตโนมัติ

**บนสไลด์**
- State หลักสูตร 3 สถานะ

```
ฉบับร่าง ──ประกาศใช้──▶ ใช้งานอยู่ ──มีฉบับใหม่ของระดับเดียวกัน──▶ ปิดใช้งาน (อ่านอย่างเดียว)
 (แก้ไข / ลบได้)
```

- กล่องข้าง: ก่อนประกาศใช้ ระบบตรวจว่า **ทุกแผนมีรายวิชา** และ **ทุกรายวิชามีครูผู้สอน** ถ้ายังไม่ครบ แสดงรายการที่ขาด

**ภาพ:** `docs/state/state-4-curriculum.png` (รูป 3.34) · `docs/activity/act-c4.png` (รูป 3.11)

**พูด:** ม.ต้น และ ม.ปลาย ใช้ได้ระดับละหนึ่งหลักสูตร · ถ้ายังไม่ครบ ฝ่ายวิชาการเลือกกลับไปแก้เฟส 3 หรือประกาศใช้ต่อได้ (ระบบเตือน ไม่บังคับ)

# D. ระบบจัดตารางสอน

เล่าแบบ **ข้อมูลเข้า → จัด → ตรวจ → เผยแพร่ → เปลี่ยน** โดยใช้ตัวอย่างเดียวตลอดทั้งชุด

> **ตัวอย่างประจำชุด:** ครูสมศรีสอน **ค22101 คณิตศาสตร์ 3** ให้ **ม.2/1** สัปดาห์ละ 3 คาบ และมีเวลาไม่ว่างที่อนุมัติแล้ว คือ **ประชุมฝ่ายวิชาการ วันจันทร์ 08:30–10:10** (ตรงกับคาบ 1–2 ของ ม.ต้น)
> โครงสร้างเวลา: ม.ต้น คาบละ 50 นาที · ม.ปลาย คาบละ 55 นาที · ทั้งสองช่วงชั้นเริ่มคาบ 1 เวลา 08:30

## D1. ข้อมูลที่ต้องมีก่อนจัด

**หัวสไลด์:** ก่อนจัดตาราง ระบบต้องรู้ว่าใครสอนอะไร ห้องไหน และเวลาไหนว่าง

**บนสไลด์**

| ข้อมูล | มาจาก | ตัวอย่าง |
|---|---|---|
| รายวิชาของแต่ละห้อง + จำนวนคาบต่อสัปดาห์ | ระบบหลักสูตร (แผนการเรียน) | ม.2/1 เรียน ค22101 สัปดาห์ละ 3 คาบ |
| ครูผู้สอนของแต่ละวิชาในแต่ละห้อง | ระบบหลักสูตร (กำหนดครูผู้สอน) | ค22101 ม.2/1 → ครูสมศรี |
| ห้องเรียน ห้องเฉพาะทาง ความจุ | ข้อมูลหลัก (อาคารสถานที่) | ห้องประจำ ม.2/1 |
| โครงสร้างเวลาของช่วงชั้น | ฝ่ายวิชาการตั้งตอนเตรียมฉบับ | ม.ต้น 8 คาบ/วัน คาบละ 50 นาที |
| กิจกรรมที่ล็อกเวลา | ฝ่ายวิชาการตั้งตอนเตรียมฉบับ | โฮมรูม · ชุมนุม |
| เวลาไม่ว่างของครู (ที่อนุมัติแล้ว) | ครูกรอก → ฝ่ายวิชาการอนุมัติ | ครูสมศรี จันทร์ 08:30–10:10 |
| *เงื่อนไขเพิ่ม (เฉพาะแบบกำหนดเงื่อนไข)* | ฝ่ายวิชาการกำหนด | คณิตเรียนช่วงเช้า |

แถบล่าง: **ข้อมูลไม่ครบ → ระบบแสดงรายการที่ขาด และยังไม่ให้เริ่มจัด**

**ภาพ:** ไม่มี (ตารางเป็นองค์ประกอบหลัก) หรือหน้าจอ `ครูผู้สอน/งานของฉัน/โปรไฟล์และเวลาไม่ว่าง` เป็นภาพเล็กข้างแถวเวลาไม่ว่าง

**พูด**
- 2 แถวบนมาจากระบบหลักสูตร ครูไม่ต้องกรอกซ้ำ (เชื่อมกับสไลด์การไหลของข้อมูล B5)
- เวลาไม่ว่างต้อง**อนุมัติแล้ว**เท่านั้นจึงใช้เป็นเงื่อนไข (เฟส 1, รูป 3.12)
- จุดตรวจความครบอยู่ในเฟส 2 (รูป 3.13) และขั้นแรกของ Algorithm (รูป 3.41)

## D4. ระบบจัดอัตโนมัติอย่างไร

**หัวสไลด์:** ระบบตัดช่องที่ผิดเงื่อนไขบังคับทิ้งก่อน แล้วให้คะแนนช่องที่เหลือเพื่อเลือกช่องที่ดีที่สุด

**บนสไลด์** (เล่าด้วยตัวอย่าง ค22101 ม.2/1 ทีละขั้น)

```
งาน: วาง ค22101 ม.2/1 คาบที่ 1 จาก 3

① ตัดทิ้ง (Hard — ห้ามละเมิด)
   ✗ จันทร์ คาบ 1–2      ครูสมศรีประชุม (เวลาไม่ว่างที่อนุมัติแล้ว)
   ✗ ช่องที่ครูสมศรีสอน ม.2/2 อยู่แล้ว
   ✗ ช่องที่ ม.2/1 มีวิชาอื่นอยู่แล้ว / ช่องโฮมรูม ชุมนุม
② ให้คะแนนช่องที่เหลือ (Soft — ควรทำตาม)
   + ช่วงเช้า (ถ้ากำหนดให้คณิตเรียนเช้า)
   − วันนั้นมีคณิตแล้ว (ให้กระจายตลอดสัปดาห์)
③ วางลงช่องที่คะแนนสูงสุด → ทำซ้ำกับคาบถัดไป
```

ข้างภาพ 1 บรรทัด: **ลำดับงาน = ยากก่อนง่าย** (คาบคู่ → ห้องเฉพาะทาง → ครูหลายคน → วิชาสำคัญ)

**ภาพ:** `docs/algorithm/algo-1-auto-schedule.png` (รูป 3.41) เป็นภาพเล็ก หรือเก็บไว้ใน backup

**พูด**
- ก่อนเริ่ม ระบบแตกภาระสอนทุกห้องเป็นงานทีละคาบ แล้วเรียงงานยากก่อน เพราะงานยากมีช่องที่เป็นไปได้น้อย ถ้าวางทีหลังมักไม่เหลือช่อง
- คาบคู่ที่หาช่องติดกันไม่ได้ แตกเป็นคาบเดี่ยวแล้วจัดใหม่
- วางไม่ได้ → รายงานเหตุผลที่พบบ่อยที่สุด เช่น "ครูติดสอนห้องอื่นในทุกช่องที่เหลือ"
- (ถ้าถูกถาม) เงื่อนไขทั้งหมด Hard 13 ข้อ Soft 4 ข้อ · แบบอัตโนมัติใช้ Hard 8 Soft 1 · แบบกำหนดเงื่อนไขใช้ครบ (ตาราง 3.4 ใน backup)

## D5. ตรวจการชน

**หัวสไลด์:** ระบบตรวจการชนด้วยเวลาจริงตามนาฬิกา และแยกสิ่งที่ต้องแก้ออกจากสิ่งที่แค่เตือน

**บนสไลด์**

ซ้าย: ตัวอย่างที่เลขคาบต่างกันแต่เวลาทับกัน

```
ม.ต้น  คาบ 4   11:00 ──────────── 11:50
ม.ปลาย คาบ 3   10:20 ───────── 11:15
                       └ ทับ 11:00–11:15 ┘
ครูคนเดียวกันสอน ม.2/1 คาบ 4 และ ม.5/1 คาบ 3 → Conflict
```

ขวา: 2 ระดับ (ตัวอย่างฝั่งละ 3 ข้อ)

| ต้องแก้ก่อนเผยแพร่ (Conflict) | แค่เตือน เผยแพร่ได้ |
|---|---|
| ครูสอนซ้อนเวลา | ครูภาระสอนเกิน 24 คาบ/สัปดาห์ |
| ห้องเดียวกันมี 2 วิชาพร้อมกัน | ห้องไม่ตรงประเภทที่วิชาต้องการ |
| ตรงเวลาไม่ว่างของครูที่อนุมัติแล้ว | ครูสอนติดกันเกินที่กำหนด |

**ภาพ:** หน้าจอตอนแจ้ง Conflict `presentation/deck/pptx-src/shots/timetable_conflict-report.png`

**พูด**
- ถ้าเทียบแค่เลขคาบ คาบ 4 กับคาบ 3 ไม่ชน แต่เวลาจริงทับกัน 15 นาที
- ตรวจทุกครั้งที่วางหรือย้ายคาบ ทั้งจัดเองและจัดอัตโนมัติ
- (ถ้าถูกถาม) ทั้งหมด Conflict 9 ข้อ คำเตือน 4 ข้อ (ตาราง 3.5 ใน backup)

## D6. เผยแพร่และเปลี่ยนตาราง

**หัวสไลด์:** ตารางที่เผยแพร่แล้วแก้ตรงไม่ได้ การเปลี่ยนทุกครั้งสร้างฉบับใหม่

**บนสไลด์**
- State ฉบับตารางสอนเป็นภาพหลัก

```
ฉบับร่าง ──เผยแพร่ (ไม่มี Conflict)──▶ ฉบับเผยแพร่ ──มีฉบับใหม่──▶ ฉบับเก่า
 (จัด / ตรวจชนได้เฉพาะที่นี่)              (แก้ไม่ได้)
     ▲                                        ▲
     └ คัดลอกเป็นร่างใหม่                      └ อนุมัติคำร้องของครู → สร้างฉบับเผยแพร่ใหม่ทันที
```

- กล่องข้าง "คำร้องของครู": ครูเลือกคาบ → ระบบเสนอเฉพาะเป้าหมายที่ไม่ชน → ฝ่ายวิชาการดูตารางก่อน/หลัง → อนุมัติ / อนุมัติพร้อมแก้ไข / ไม่อนุมัติ

**ภาพ:** `docs/state/state-2-timetable-version.png` (รูป 3.32) · ภาพเล็ก `presentation/deck/pptx-src/shots/timetable_publish-blocked.png`

**พูด**
- หนึ่งภาคเรียนมีฉบับเผยแพร่ได้ทีละฉบับ ระบบบันทึกประวัติและแจ้งเตือนครูทุกครั้ง
- ตัวอย่าง: ครูสมศรีขอย้ายคาบคณิตวันพุธ → ระบบเสนอเฉพาะช่องที่ไม่ชน → อ.สุนิสาอนุมัติ → เกิดฉบับเผยแพร่ใหม่ ฉบับเดิมเป็นฉบับเก่า
- ครูยกเลิกคำร้องได้เฉพาะตอนรออนุมัติ · ไม่อนุมัติหรืออนุมัติพร้อมแก้ไขต้องกรอกหมายเหตุ (State คำร้อง รูป 3.33 ใน backup)

# E. ระบบเช็คชื่อ

## E1. เปิดระบบ + เช็คชื่อรายคาบ

**หัวสไลด์:** ครูเช็คชื่อรายคาบโดยเริ่มจาก "มา" ทุกคน แล้วแก้เฉพาะคนที่ไม่มา

**บนสไลด์**
- ผู้ใช้: ครูผู้สอน (รวมครูประจำชั้น) · UC-23, UC-24
- แถบเฟส 4 เฟส

```
1 เช็คชื่อรายคาบ → 2 แก้ไขการเช็คชื่อ → 3 ตรวจเวลาเรียนและ มส → 4 ปลด มส
```

- กฎของเฟส 1–2
  - คาบที่ต้องเช็ค = คาบในตารางที่**เผยแพร่แล้ว** ไม่รวมวันหยุดของโรงเรียน
  - คาบวันนี้ตั้งค่าเริ่มต้นเป็น **มา** ทุกคน · คาบย้อนหลังครูเลือกค่าเริ่มต้นเอง
  - สถานะ 4 แบบ: มา · สาย · ลา · ขาด
  - แก้จาก **ขาด → มา** ต้องยืนยันและกรอกเหตุผลอย่างน้อย 10 ตัวอักษร ระบบเก็บประวัติ
  - ห้องที่ส่งผลการเรียนแล้ว การเช็คชื่อถูกล็อก

**กล่องจุดเด่น** · แก้ปัญหาข้อ 5: เปิดมาเห็นคาบที่ยังไม่เช็คทันที ไม่ต้องเลือกตัวกรอง · คำนวณเวลาเรียนและ มส อัตโนมัติ แล้วส่งต่อให้ระบบคะแนน

**ภาพ:** หน้าจอ `ครูผู้สอน/เช็คชื่อ/คาบวันนี้` (เปิดมาเห็นคาบที่ยังไม่เช็คทันที) · `docs/activity/act-a1.png`, `act-a2.png`

**พูด:** เริ่มจาก "มา" ทุกคนเพราะนักเรียนส่วนใหญ่มาเรียน ครูแก้แค่ไม่กี่คน · ขาด → มา ต้องมีเหตุผล เพราะกระทบสิทธิ์สอบ

---

## E2. เวลาเรียนและ มส

**หัวสไลด์:** นักเรียนที่เวลาเรียนต่ำกว่าร้อยละ 80 ถูกจัดเป็น มส ทันที

**บนสไลด์**
- สูตรตัวใหญ่

```
เวลาเรียน (%) = (มา + สาย) ÷ คาบที่เช็คแล้ว × 100
```

- ต่ำกว่า 80% → **มส** · ใกล้เกณฑ์ → **กลุ่มเสี่ยง**
- ครูผู้สอนเห็นเวลาเรียนและ "ขาดได้อีกกี่คาบ" ของห้องที่สอน
- ครูประจำชั้นเห็นห้องตนทุกวิชา แต่**แก้สถานะที่ครูผู้สอนเช็คไม่ได้**

**ภาพ:** หน้าจอ `ครูผู้สอน/เช็คชื่อ/ห้องที่ฉันสอน` และ `ห้องประจำชั้น ม.2-1` · `docs/activity/act-a3.png` (รูป 3.20)

**พูด:** หารด้วยคาบที่เช็คแล้ว ไม่ใช่คาบทั้งภาค จึงเห็นแนวโน้มตั้งแต่กลางภาค · เกณฑ์ 80% ตั้งค่าได้

---

## E3. ปลด มส

**หัวสไลด์:** การปลด มส ต้องมีบันทึกอนุมัติจากผู้บริหาร และไม่เปลี่ยนเวลาเรียน

**บนสไลด์**
- flow ย่อ: ครูรับบันทึกอนุมัติ (นอกระบบ) → เลือกนักเรียน มส → เลือกกรณี + เลขที่บันทึก + เหตุผล → ระบบบันทึก (เวลาเรียนคงเดิม)
- 2 กรณี

| กรณี | ผลการเรียน |
|---|---|
| เหตุสุดวิสัย | ตัดสินผลตามปกติ |
| เรียนชดเชย | ระดับผลการเรียนไม่เกิน 1 |

- ห้องที่ส่งผลแล้ว ปลด มส ไม่ได้ ต้องขอปลดล็อกก่อน

**ภาพ:** `docs/activity/act-a4.png` (รูป 3.21)

**พูด:** ผลจากระบบเช็คชื่อส่งต่อไปเป็นขั้นแรกของการคำนวณผลการเรียน (สไลด์ F3)

# F. ระบบบันทึกคะแนน

## F1. เปิดระบบ + โครงสร้างคะแนน

**หัวสไลด์:** ครูบันทึกคะแนนได้เมื่อโครงสร้างคะแนนรวมครบ 100%

**บนสไลด์**
- ผู้ใช้: ครูผู้สอน · ครูที่ปรึกษาชุมนุม · ครูฝ่ายวิชาการ
- แถบเฟส 7 เฟส

| เฟส | ชื่อ | UC |
|:-:|---|---|
| 1 | กำหนดโครงสร้างคะแนน | UC-11 |
| 2 | บันทึกคะแนนและคุณลักษณะฯ | UC-12, 25 |
| 3 | คำนวณผลการเรียน | UC-13, 14, 15 |
| 4 | ส่งและตรวจผลการเรียน | UC-17, 18 |
| 5 | บันทึกผลสอบซ่อม | UC-20 |
| 6 | ขอปลดล็อกผลการเรียน | UC-19 |
| 7 | ชุมนุมและผลกิจกรรม ผ/มผ | UC-26 |

- กล่องเน้นเฟส 1: เริ่มจากโครงสร้างตั้งต้นของรายวิชา → ครูปรับองค์ประกอบ คะแนนเต็ม สัดส่วน ตัวชี้วัด → **สัดส่วนรวม = 100%** จึงบันทึกได้

**กล่องจุดเด่น** · แก้ปัญหาข้อ 2, 6, 7: ตั้งสัดส่วนคะแนนได้ · นำเข้าคะแนนจาก Excel/CSV · คำนวณเกรดใหม่เองทุกครั้งที่ข้อมูลเปลี่ยน ไม่ต้องกดประมวลผลแบบ SGS

**ภาพ:** `docs/activity/act-g1.png` (รูป 3.22) · หน้าจอแท็บโครงสร้างคะแนนใน `ครูผู้สอน/บันทึกคะแนน/รายวิชาของฉัน`

**พูด:** ระบบเดิมตั้งสัดส่วนไม่ได้ (ปัญหาข้อ 6) · ตัวชี้วัดผูกกับองค์ประกอบคะแนน

## F2. บันทึกคะแนน

**หัวสไลด์:** ครูกรอกคะแนนเองหรือนำเข้าจาก Excel และ CSV ได้ โดยระบบตรวจช่วงคะแนนให้

**บนสไลด์**
- 2 ทาง: กรอกเอง (ใส่ ร = รอส่งงาน, ข = ขาดสอบ ได้) · นำเข้าไฟล์ Excel / CSV
- ระบบตรวจ: เป็นตัวเลข **0 ถึงคะแนนเต็ม** ไม่ผ่านให้แก้ก่อน
- บันทึกประวัติการแก้ไขทุกครั้ง
- ประเมินคุณลักษณะอันพึงประสงค์ และการอ่าน คิดวิเคราะห์ เขียน ในหน้าเดียวกัน

**ภาพ:** หน้าจอแท็บกรอกคะแนน `ครูผู้สอน/บันทึกคะแนน/รายวิชาของฉัน` (รูป 4.61) · `docs/activity/act-g2.png`

**พูด:** การนำเข้าคะแนนจากไฟล์คือสิ่งที่ SchoolBright และ SGS ไม่มี (SGS ต้องใช้โปรแกรมเสริมภายนอก) · การนำเข้าไฟล์ใหญ่ทำเป็นงานเบื้องหลัง

## F3. คำนวณผลการเรียน

**หัวสไลด์:** ระบบตรวจเวลาเรียนและความครบของคะแนนก่อน แล้วจึงตัดเกรด

**บนสไลด์** (ลำดับการตรวจ รูป 3.42)

```
1 เวลาเรียน < 80% และไม่ได้ปลด มส  → มส
2 มีองค์ประกอบเป็น ร หรือ ข          → ร
3 คะแนนยังไม่ครบ                     → ยังไม่ตัดสิน
4 รวมคะแนนตามสัดส่วน → ปัดเป็นจำนวนเต็ม → เกรด 8 ระดับ (0–4)
5 ได้ 0                              → มีสิทธิ์สอบซ่อม
```

**ภาพ:** `docs/algorithm/algo-2-grade-result.png` (รูป 3.42)

**พูด**
- คำนวณใหม่อัตโนมัติทุกครั้งที่คะแนน เวลาเรียน หรือผลสอบซ่อมเปลี่ยน ครูไม่ต้องกดประมวลผลเอง (ต่างจาก SGS)
- ข้อมูลจากระบบเช็คชื่อมาเป็นขั้นแรก
- ปลด มส กรณีเรียนชดเชย ระดับไม่เกิน 1

---

## F4. ส่ง ตรวจ และอนุมัติ

**หัวสไลด์:** เมื่อครูส่งผล ระบบล็อกคะแนน เวลาเรียน และการปลด มส ของห้องนั้นพร้อมกัน

**บนสไลด์**
- State ผลการเรียน 4 สถานะ (กรอบสีส้มรอบ 2 สถานะที่ล็อก)

```
ยังไม่ตั้งโครงสร้าง ──ครบ 100%──▶ กำลังบันทึก ──ส่งผล──▶ [ รอตรวจ ] ──อนุมัติ──▶ [ อนุมัติแล้ว ]
                                     ▲                     │
                                     └──── ตีกลับ ─────────┘  (พร้อมเหตุผล + หมุดข้อสังเกต)
```

- ก่อนส่ง: ระบบแสดงรายการตรวจ ถ้าคะแนนไม่ครบส่งไม่ได้
- ฝ่ายวิชาการ: ดูสถานะการส่งของทั้งโรงเรียน · ตรวจแบบ**อ่านอย่างเดียว** · ปักหมุดข้อสังเกต → อนุมัติ / ตีกลับ

**ภาพ:** `docs/state/state-1-grading.png` (รูป 3.31) · `docs/activity/act-g4.png` (รูป 3.25) · หน้าจอ `ครูวิชาการ/ผลการเรียน/กล่องงาน`

**พูด**
- ตีกลับไม่ใช่สถานะแยก แต่กลับไป "กำลังบันทึก" พร้อมเหตุผล
- ชุมนุมไม่มีโครงสร้างคะแนน จึงเริ่มที่ "กำลังบันทึก"
- ทุกการเปลี่ยนสถานะบันทึกเป็นประวัติการส่งผล
- ฝ่ายวิชาการแก้คะแนนแทนครูไม่ได้

---

## F5. แก้ผลหลังส่ง: สอบซ่อมและขอปลดล็อก

**หัวสไลด์:** หลังส่งผลแล้ว ครูแก้ผลได้ผ่านการสอบซ่อมหรือการขอปลดล็อกเท่านั้น

**บนสไลด์** (2 คอลัมน์)

| สอบซ่อม (UC-20) | ขอปลดล็อก (UC-19) |
|---|---|
| เฉพาะนักเรียนที่ได้ 0 | ห้องที่ส่งแล้วหรืออนุมัติแล้ว |
| สอบได้ **ไม่เกิน 2 ครั้ง** | ครูกรอกเหตุผล → ฝ่ายวิชาการพิจารณา |
| ได้ ≥ 50% → ระดับ **1** | อนุมัติ → กลับเป็น "กำลังบันทึก" |
| ครั้งที่ 2 ไม่ผ่าน → คง 0 ต้องเรียนซ้ำ | ไม่อนุมัติ → คงสถานะเดิม + แสดงเหตุผล |
| ห้องที่รอตรวจ บันทึกไม่ได้ | ระหว่างรอ สถานะเดิมยังอยู่ (ติดป้ายคำขอ) |

**ภาพ:** `docs/activity/act-g5.png`, `act-g6.png` (รูป 3.26, 3.27) · หน้าจอ `ครูผู้สอน/บันทึกคะแนน/บันทึกผลสอบซ่อม`

**พูด:** ชุมนุม (เฟส 7) ครูที่ปรึกษาบันทึก ผ/มผ แล้วส่งผลผ่านขั้นตอนเดียวกับเฟส 4 · ระบบตรวจจำนวนรับและไม่ให้นักเรียนอยู่ชุมนุมประเภทเดียวกันซ้ำ

# G. ระบบออกรายงาน

## G1. รายงานตามสิทธิ์

**หัวสไลด์:** รายงานแสดงตามสิทธิ์ ครูผู้สอนเห็นเฉพาะห้องที่ตนสอน

**บนสไลด์**
- flow ย่อ: เลือกเมนูรายงาน → ระบบตรวจบทบาท แสดงเฉพาะรายงานที่มีสิทธิ์ → เลือกเงื่อนไข → แสดงตาราง/สรุป → ค้นหา กรอง ดูรายคน · ส่งออก Excel / PDF

| ครูฝ่ายวิชาการ | ครูผู้สอน |
|---|---|
| ภาพรวมความคืบหน้าและนักเรียนที่ต้องติดตาม · ผลการเรียน · คะแนนรายวิชา · คะแนนเฉลี่ยรายปี · นักเรียนต้องปรับปรุง · ผลสอบซ่อม · ระเบียนสะสม / GPAX · การเข้าเรียน · ผู้ไม่มีสิทธิ์สอบ | การเข้าเรียน · ผู้ไม่มีสิทธิ์สอบ (เฉพาะห้องที่สอน) |

- กรองได้ตาม ปีการศึกษา · ภาคเรียน · ระดับชั้น · ห้อง · รายวิชา (เลือกต่อกันเป็นลำดับ และจำค่าที่ค้นล่าสุด)

**กล่องจุดเด่น** · แก้ปัญหาข้อ 8: เปิดมาเห็นภาคเรียนปัจจุบันทันที · ค้นหา เรียง กรองในตารางได้ · แสดงตามสิทธิ์ และใช้เฉพาะผลที่อนุมัติแล้ว

**ภาพ:** หน้าจอ 2 บทบาทคู่กัน `ครูวิชาการ/รายงานวิชาการ/ภาพรวม` กับ `ครูผู้สอน/งานของฉัน/รายงานการเข้าเรียน` (รูป 4.19, 4.58) · `docs/activity/act-r1.png` (รูป 3.29)

**พูด**
- ระบบรายงานไม่มีตารางของตัวเอง อ่านจากกลุ่มอื่น และใช้ผลการเรียนที่**อนุมัติแล้ว**เท่านั้น
- ตอบปัญหาข้อ 8: เปิดมาเห็นภาคปัจจุบันทันที ค้นหาและเรียงในตารางได้
- ดูข้อมูลหลักสูตรและรายวิชา (UC-1) ก็อยู่ในเมนูนี้ (รูป 3.30)
