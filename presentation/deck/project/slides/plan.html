เทอม 2 จะล็อกขอบเขตในเดือนที่ 1
แล้วพัฒนาระบบย่อยตามลำดับที่ข้อมูลส่งต่อกัน

ลำดับงานความเสี่ยงที่กระทบ และแผนรองรับ
เดือนที่ 1ยืนยันและล็อกขอบเขต ให้ผู้ใช้ทดลองต้นแบบแล้วปรับแก้ และตกลงข้อกำหนด API กับ Service Bเทอม 1 ขอบเขตเปลี่ยนบ่อย จึงล็อกหลังเดือนที่ 1 และตกลง API ตั้งแต่ต้น เผื่อ Service B เปลี่ยนวิธีตรวจสิทธิ์
พัฒนาหลักสูตร ตารางสอน เช็คชื่อ บันทึกคะแนน แล้วจึงออกรายงาน ทำ Unit Test ไปพร้อมกันถ้าพัฒนาไม่ทัน ทำระบบหลักให้เสร็จก่อน แล้วเลื่อนการจัดตารางอัตโนมัติแบบกำหนดเงื่อนไขและรายงานบางประเภทเป็นงานเสริม
เชื่อมต่อบูรณาการกับระบบของกลุ่มอื่นทุก 2 สัปดาห์ และทำ Integration Testถ้าระบบของกลุ่มอื่นเสร็จไม่ทัน ใช้ระบบจำลองที่ตอบตามข้อตกลง API ไปก่อน
ทดสอบSystem Test, Load Test และ User Acceptance Test แล้วปรับปรุงตามผลถ้าหาผู้ใช้จริงมาทำ UAT ไม่ได้ ให้อาจารย์หรือเพื่อนสวมบทครูตาม Persona

ที่มา: รายงานข้อ 5.3.1 ตารางที่ 5.3 (ช่วงเดือนของแต่ละกิจกรรม) และตารางที่ 5.4

I 1:00 — เทอม 2 มีสี่เดือน ปัญหาใหญ่ของเทอม 1 คือขอบเขตเปลี่ยนบ่อย จนต้องกลับไปแก้ use case และ ER หลายรอบ เดือนแรกเราจึงล็อกขอบเขต ให้ผู้ใช้ลองต้นแบบ และตกลง API กับ Service B ให้เสร็จ จากนั้นพัฒนาตามลำดับที่ข้อมูลส่งต่อกัน หลักสูตรเดือนแรก ตารางสอน เช็คชื่อ และคะแนนเดือนสอง รายงานเดือนสาม ทดสอบทั้งระบบเดือนสามถึงสี่ และให้ผู้ใช้ทดสอบเดือนสุดท้าย ความเสี่ยงแต่ละข้อเขียนไว้ข้างงานที่มันกระทบ เราจะรายงานความคืบหน้ากับอาจารย์ที่ปรึกษาทุกสองสัปดาห์
