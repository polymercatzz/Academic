# ฐานข้อมูล — Academic Report

ออกแบบฐานข้อมูลจริงของทั้งระบบ (PostgreSQL) แทนข้อมูลจำลองที่แต่ละโมดูลมีของตัวเอง รอบนี้ทำแค่ **Data dictionary และ ER** ยังไม่มี DDL

ต่อยอดจาก ER ของระบบบันทึกคะแนน ([grading/docs/er-data-dictionary.md](../../grading/docs/er-data-dictionary.md) ฉบับที่ 2) เมื่อขอบเขตไหนเสร็จ ให้ถือไฟล์ในโฟลเดอร์นี้เป็นหลัก

## ขอบเขต

ทำทีละขอบเขตตามลำดับการพึ่งพา ขอบเขตหลังอ้าง FK ไปหาขอบเขตก่อนหน้าได้ แต่ห้ามอ้างย้อนกลับ

| # | ขอบเขต | ไฟล์ | สถานะ |
|---|---|---|---|
| 0 | ข้อมูลหลักที่ใช้ร่วมกัน: ปีการศึกษา ภาคเรียน ระดับชั้น กลุ่มสาระ นักเรียน ห้องเรียน ครูประจำชั้น | [00-core.md](00-core.md) | ร่าง |
| 1 | หลักสูตร: รายวิชา โครงสร้างคะแนนตั้งต้น ตัวชี้วัด หลักสูตร หน่วยกิตขั้นต่ำ แผนการเรียน ห้องเรียนที่สอนและครูผู้สอน ชุมนุม | [01-curriculum.md](01-curriculum.md) | ร่าง |
| 2 | บันทึกคะแนน: โครงสร้างคะแนน คะแนน คุณลักษณะฯ เกณฑ์ ผลการเรียน สอบซ่อม การตรวจอนุมัติ | [02-grading.md](02-grading.md) | ร่าง |

**นอกขอบเขต:** การจัดการผู้ใช้ระบบ (`app_user`, `role`, `user_role` บัญชี รหัสผ่าน สิทธิ์) เป็นงานของ **ฝ่ายทะเบียน** ใน ER วาดไว้ในกรอบเส้นประ "ฝ่ายทะเบียน (นอกขอบเขต)" ฟิลด์ที่เราต้องใช้อยู่ที่ [00-core.md หัวข้อ 3.1](00-core.md#31-ตารางของฝ่ายทะเบียน-นอกขอบเขต)

## ข้อตกลง

ใช้กับทุกขอบเขต ถ้าขอบเขตไหนต้องแหกข้อตกลง ให้เขียนเหตุผลไว้ในไฟล์ของขอบเขตนั้น

### การตั้งชื่อ

| เรื่อง | ข้อตกลง | ตัวอย่าง |
|---|---|---|
| ตาราง | `snake_case` เอกพจน์ | `student_classroom` (ER เดิมเรียก `StudentClassroom`) |
| PK | `<ชื่อตาราง>_id` | `student_id` |
| FK | ชื่อเดียวกับ PK ที่อ้าง ถ้าอ้างตารางเดียวกันหลายครั้ง ให้ใช้ชื่อตามหน้าที่ | `user_id`, `checked_by`, `decided_by` |
| คำสงวน | เลี่ยงชื่อที่เป็นคำสงวนของ PostgreSQL | `app_user` ไม่ใช่ `user` |

PostgreSQL แปลงชื่อที่ไม่อยู่ในเครื่องหมายคำพูดเป็นตัวพิมพ์เล็ก ถ้าใช้ `PascalCase` แบบ ER เดิม ต้องใส่ `"..."` ทุกครั้งที่ query จึงเปลี่ยนเป็น `snake_case` ไฟล์ของแต่ละขอบเขตมีตารางเทียบชื่อกับ ER เดิม

### ชนิดข้อมูล

| ใช้กับ | ชนิด | หมายเหตุ |
|---|---|---|
| PK / FK ทั่วไป | `INTEGER GENERATED ALWAYS AS IDENTITY` | ตารางที่โตเร็วมาก (log, การเช็คชื่อ, คะแนน) ใช้ `BIGINT` |
| ปีการศึกษา | `SMALLINT` | เก็บเป็น พ.ศ. เช่น `2569` |
| ข้อความที่มีความยาวจำกัดทางธุรกิจ | `VARCHAR(n)` | รหัส ชื่อ |
| ข้อความอิสระ | `TEXT` | เหตุผล หมายเหตุ |
| ค่าจากรายการตายตัว | `VARCHAR(n)` + `CHECK (... IN (...))` | ไม่ใช้ `ENUM` ของ PostgreSQL เพราะเพิ่มหรือลบค่าทีหลังยาก |
| คะแนน สัดส่วน ร้อยละ | `NUMERIC(p,s)` | ไม่ใช้ `REAL` / `DOUBLE` เพราะปัดเศษผิด |
| วันที่ | `DATE` | |
| เวลาที่เกิดเหตุการณ์ | `TIMESTAMPTZ` | ER เดิมใช้ `DATETIME` |
| เวลาในตาราง (คาบ) | `TIME` | |
| ใช่ / ไม่ใช่ | `BOOLEAN` | |

### กติกาอื่น

- **ไม่ลบข้อมูลหลัก** นักเรียน ครู รายวิชา ใช้คอลัมน์ `status` แทนการลบ เพราะผลการเรียนย้อนหลังต้องอ้างถึงได้
- **`created_at` / `updated_at`** มีในตารางที่ผู้ใช้แก้ได้ เป็น `TIMESTAMPTZ NOT NULL DEFAULT now()`
- **ค่าที่คำนวณได้** ไม่เก็บ ยกเว้นเป็น snapshot ที่ต้องคงค่าเดิมแม้ข้อมูลต้นทางเปลี่ยน (เช่น ผลการเรียนที่อนุมัติแล้ว) และต้องเขียนเหตุผลไว้
- **กฎที่ใช้ constraint ไม่ได้** เขียนไว้ในหัวข้อ "กฎทางธุรกิจ" ของแต่ละขอบเขต

## รูปแบบไฟล์ของแต่ละขอบเขต

1. ขอบเขตและที่มา: หน้าจอไหนในระบบจำลองใช้ข้อมูลชุดนี้
2. ER (Mermaid `erDiagram`)
3. Data dictionary: ฟิลด์ · ชนิดข้อมูล · คีย์ · Null · คำอธิบาย
4. กฎทางธุรกิจ
5. เทียบกับ ER เดิม: ตารางหรือฟิลด์ที่เปลี่ยน และเหตุผล
6. คำถามที่ยังเปิดอยู่
