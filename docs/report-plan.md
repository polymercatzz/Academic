### โครงสร้าง section ในไฟล์ Word (ห้ามลบ section break)

| section | ช่วง | เลขหน้า |
|---|---|---|
| 1 | ปก | ไม่มี |
| 2 | บทคัดย่อ → สารบัญ | I, II, III กึ่งกลางล่าง (footer) |
| 3, 4, 5, … | บทละ 1 section | อารบิกมุมบนขวา (header) ต่อเนื่องจากบท 1, หน้าแรกของบทไม่แสดง (Different First Page) |

**เพิ่มบทใหม่ (บท 4, 5):** ท้ายบทก่อนหน้าใส่ Layout → Breaks → **Section Break (Next Page)** แทน Page Break — header/footer จะติดมาจากบทก่อนหน้าเอง ตรวจว่า "Different First Page" ติ๊กอยู่และไม่ได้ตั้ง "Start at" ใหม่

## ข้อตกลงในการแก้ไข

- **รูปแบบเล่มทั้งหมดยึดตาม [Rule/README.md](../Rule/README.md)** (สรุปจากคู่มือและ template ของคณะ) — ฟอนต์ ขนาดหัวเรื่อง ระยะขอบ เลขหน้า ตาราง/รูป บรรณานุกรม และ checklist ก่อนส่ง ในแผนนี้อ้างเป็น "Rule §n"
- **ทุกจุดที่แก้ไขหรือเพิ่มในไฟล์ Word ให้เป็นตัวหนังสือสีแดง** เพื่อให้ตรวจทานได้ง่าย เมื่อยืนยันแล้วจึงเปลี่ยนกลับเป็นสีดำ — คู่มือกำหนดหมึกดำทั้งเล่ม ต้องไม่มีสีแดงค้างตอนส่ง (Rule §9)
- การส่งออกเอกสาร (PDF/Excel) **ตัดเฉพาะใน use case** — ขอบเขตบท 1 และ FR10 คงไว้
- ระบบที่เกี่ยวข้องในบท 2 รีวิว **SchoolBright** เป็นหลัก
- Activity Diagram เปลี่ยนเป็น **swimlane แยกตามระบบย่อย 5 ระบบ รูปละ 1 เฟส รวม 23 รูป อยู่ในภาคผนวก ข** ครบ 26 UC (ตามคอมเมนต์ในเล่ม 2026-11-05, ทำ 2026-11-07) — บท 3 เหลือรูปภาพรวม + ตารางเฟส · ชื่อช่องใช้ชื่อบทบาทตาม UC · ทุกขั้นตอนมีเลข (2.1 = เฟส 2 ขั้นที่ 1) · ข้ามเฟสใช้วงกลมเลขขั้นตอน ("มาจากเฟส n" / "ไปเฟส n")
- ER และ Data Dictionary อิงตาม [`docs/database/`](database/README.md) แยกเป็นแพ็กเกจ
- เช็คชื่อ ชุมนุม คุณลักษณะฯ/ตัวชี้วัด **อยู่ในขอบเขต** (ตัดสิน 2026-11-04) — แก้ข้อ 1.3.4 แล้ว

### ส่วนที่เพิ่ม — เนื้อหาการทำงานของระบบ (แผน 2026-11-05)

**ปัญหา:** ในเล่มตอนนี้ราว 70% ของข้อความเป็น Data Dictionary (~35,000 ตัวอักษร) กับคำอธิบาย Use case ในภาคผนวก (~45,000 ตัวอักษร) ส่วนบท 1–3 ที่เหลือมีราว 31,000 ตัวอักษร บท 3 บอกได้ว่าระบบ**มีอะไร** (FR, UC, ตาราง) แต่ยังไม่ได้อธิบายว่าระบบ**ทำงานอย่างไร** ทั้งเล่มไม่มี State diagram, Sequence diagram หรือการออกแบบอัลกอริทึม และทฤษฎีในบท 2 (Timetabling Problem, เกณฑ์ผลการเรียน) ยังไม่ได้นำมาใช้ในบท 3

**หลักการ:** ไม่ต้องคิดเนื้อหาใหม่ ข้อมูลส่วนใหญ่อยู่ใน ADR และโค้ดเดโมแล้ว แค่นำมาเขียนเป็นรูปและข้อความในเล่ม · ทุกส่วนที่เพิ่มเป็นสีแดง · รูปวาดใน draw.io แบบขาวดำเหมือนรูปอื่น (เก็บ `.drawio` + `.png`) · ทุกรูปและหัวข้อต้องอ้างเลข UC หรือ FR
