# Personas

ตัวละครกลางของระบบ ใช้ทั้งตอนออกแบบ (ใคร ต้องการอะไร ทำงานอะไร) และเป็นตัวตนในข้อมูลจำลองตอนสาธิต ทุกโมดูลต้องใช้ชุดเดียวกันนี้ นิยามบทบาทและสิทธิ์อยู่ที่ [actors.md](actors.md)

> **สถานะ:** ตกลงชุดตัวละครแล้วเมื่อ 2026-11-03 แต่โค้ดยังไม่ตรงกับเอกสารนี้ ดู [ช่องว่างกับโค้ดปัจจุบัน](#ช่องว่างกับโค้ดปัจจุบัน)
> หัวข้อ "ปัญหาในระบบเดิม" ของทุก persona ยังรอข้อมูลจริง

## สรุป

| Persona | ตำแหน่ง | บทบาทในระบบ | ใช้ใน demo |
|---|---|---|---|
| [อ.สุนิสา ปัญญาดี](#อสุนิสา-ปัญญาดี--หัวหน้างานวิชาการ) | หัวหน้างานวิชาการ | admin | ผู้ใช้หลักของมุมมอง admin ทุกโมดูล |
| [ครูสมศรี ใจดี](#ครูสมศรี-ใจดี--ครูคณิตศาสตร์-และกรรมการฝ่ายวิชาการ) | ครูคณิตศาสตร์ ครูประจำชั้น ม.2/1 กรรมการฝ่ายวิชาการ | ครู + admin | ผู้ใช้หลักของมุมมองครูทุกโมดูล และเคสคนเดียวมีสองบทบาท |
| [ครูประภาพร ศรีสุข](#ครูประภาพร-ศรีสุข--เจ้าหน้าที่วิชาการ) | ครูภาษาไทย เจ้าหน้าที่วิชาการ | ครู + admin | ตัวประกอบ: ผู้ตรวจคนอื่นในประวัติการตรวจ ไม่ได้ล็อกอิน |
| [นักเรียน ม.2/1](#นักเรียน-ม21--ตัวอย่างในเส้นเรื่อง) | นักเรียน | ไม่ใช่ผู้ใช้ | เส้นเรื่องตอนสาธิตเช็คชื่อ ผลการเรียน และรายงาน |

กติกาของชุดตัวละคร

- persona หนึ่งตัวมีชื่อ ตำแหน่ง และรหัสเดียวกันในทุกโมดูล
- ตัวประกอบ (ครูคนอื่นในข้อมูลจำลอง) ต้องไม่ใช้ชื่อหรือนามสกุลซ้ำกับ persona หลัก
- เรื่องราวต้องต่อกันข้ามโมดูลได้ เช่น ห้องที่ครูสมศรีสอนในตารางสอน ต้องเป็นห้องเดียวกับที่ครูสมศรีกรอกคะแนนและเช็คชื่อ

## อ.สุนิสา ปัญญาดี — หัวหน้างานวิชาการ

| | |
|---|---|
| บทบาท | admin |
| สังกัด | กลุ่มกิจกรรมพัฒนาผู้เรียน (ไม่มีคาบสอนวิชาหลัก) |
| ใช้ระบบเมื่อ | ช่วงเตรียมภาคเรียน (หลักสูตร มอบหมายสอน จัดตาราง) ระหว่างภาค (คำร้อง) และช่วงปลายภาค (ตรวจผลการเรียน รายงาน) |

**เป้าหมาย**

- ตารางสอนของภาคเรียนเผยแพร่ได้ทันเวลา ไม่มี Conflict และเคารพเวลาไม่ว่างของครูที่อนุมัติแล้ว
- เปลี่ยนตารางระหว่างภาคได้โดยย้อนดูได้ว่าใครเปลี่ยนอะไรเพราะอะไร
- รู้ว่าห้องไหนยังไม่ส่งผลการเรียน และตรวจหรืออนุมัติได้เร็วโดยไม่ต้องแก้คะแนนแทนครู
- ได้รายงานภาพรวมสำหรับผู้บริหารและการติดตามนักเรียน

**งานหลักและหน้าที่ใช้**

| งาน | หน้า |
|---|---|
| ดูแลหลักสูตร แผนการเรียน รายวิชา และมอบหมายครูผู้สอน | [จัดการหลักสูตร](../curriculum/curriculum-management.html), [จัดการรายวิชา](../curriculum/course-management.html) |
| สร้าง จัด ตรวจ Conflict และเผยแพร่ตารางสอน | [ตารางสอน](../timetable/timetable.html) |
| พิจารณาคำร้องขอเปลี่ยนการจัดและเวลาไม่ว่างของครู | [คำขออนุมัติ](../timetable/timetable-approvals.html) |
| ติดตามการส่งผล ตรวจ อนุมัติ หรือตีกลับ พิจารณาคำขอปลดล็อก | `scores.html#/a`, `#/a/inbox` |
| ดูรายงานวิชาการ | [ภาพรวม](../reports/overview.html) และเมนูรายงานวิชาการ |

**ปัญหาในระบบเดิม**

> รอข้อมูลจริง

**Scenario สาธิต**

1. เปิดหน้า [ตารางสอน](../timetable/timetable.html) คัดลอกฉบับเผยแพร่เป็นฉบับร่าง จัดอัตโนมัติ แก้ Conflict ที่เหลือ แล้วเผยแพร่
2. ไปที่ [คำขออนุมัติ](../timetable/timetable-approvals.html) อนุมัติเวลาไม่ว่างของครูสมศรี และพิจารณาคำร้องขอเปลี่ยนการจัด ระบบสร้างฉบับเผยแพร่ใหม่ให้ทันที
3. ช่วงปลายภาค เปิดกล่องงานผลการเรียน อนุมัติหลายห้องพร้อมกัน แล้วตีกลับห้องที่ผิดปกติพร้อมปักหมุดข้อสังเกต

## ครูสมศรี ใจดี — ครูคณิตศาสตร์ และกรรมการฝ่ายวิชาการ

| | |
|---|---|
| บทบาท | ครู (หลัก) + admin (ได้รับบทบาทฝ่ายวิชาการเพิ่ม) |
| ตำแหน่ง | ครูชำนาญการ กลุ่มสาระการเรียนรู้คณิตศาสตร์ |
| สอน (2569/1) | ค22101 คณิตศาสตร์ 3 ม.2/1, ม.2/2, ม.2/3 · ค22201 คณิตศาสตร์เพิ่มเติม 3 ม.2/1 · ว22103 เทคโนโลยี 3 (วิทยาการคำนวณ) ม.2/1 |
| ครูประจำชั้น | ม.2/1 |
| ใช้ระบบเมื่อ | ทุกวัน (เช็คชื่อรายคาบ) ต้นภาค (เวลาไม่ว่าง โครงสร้างคะแนน) ปลายภาค (กรอกคะแนนและส่งผล) |

**เป้าหมาย**

- รู้ตารางสอนของตนเองและห้องที่ต้องไปสอน ไม่ถูกจัดคาบตรงกับเวลาประชุมฝ่ายวิชาการ
- เช็คชื่อได้เร็วในต้นคาบ และรู้ล่วงหน้าว่านักเรียนคนไหนใกล้ มส
- กรอกคะแนนโดยไม่ต้องคำนวณเอง เห็นทันทีถ้ากรอกผิด และส่งผลได้ครั้งเดียวผ่าน
- ในฐานะครูประจำชั้น เห็นการขาดเรียนของนักเรียนในห้องตนทุกวิชา
- ในฐานะกรรมการฝ่ายวิชาการ ช่วยตรวจผลการเรียนได้ รวมถึงห้องที่ตนสอนเอง โดยระบบติดป้าย "ตรวจงานตนเอง" ([grading ADR 0007](../grading/docs/adr/0007-self-review-allowed-with-label.md))

**งานหลักและหน้าที่ใช้**

| งาน | หน้า |
|---|---|
| ดูตารางสอนของตนเอง ตารางเรียนรายห้อง และตารางการใช้ห้อง ยื่นคำร้องขอเปลี่ยนการจัด | [ตารางสอนของฉัน](../timetable/my-timetable.html) |
| กรอกเวลาไม่ว่าง (ประชุมฝ่ายวิชาการเช้าวันจันทร์) | [โปรไฟล์และเวลาไม่ว่าง](../timetable/teacher-profile.html) |
| เช็คชื่อรายคาบ ดูเวลาเรียนและนักเรียนใกล้ มส | `attendance.html#/`, `#/sections` |
| ติดตามนักเรียนห้องประจำชั้น | `attendance.html#/h`, `#/h/sum` |
| ตั้งโครงสร้างคะแนน กรอกคะแนน ส่งผล แก้ตามที่ถูกตีกลับ ขอปลดล็อก | `scores.html#/`, `#/s/<id>` |
| ตรวจผลการเรียนในมุมมองฝ่ายวิชาการ | `scores.html#/a` (สลับมุมมอง) |

**ปัญหาในระบบเดิม**

> รอข้อมูลจริง · ที่มีอยู่ใน repo ตอนนี้คือตาราง "เทียบกับระบบเดิม" ของหน้ากรอกคะแนนใน [grading/README.md](../grading/README.md#เทียบกับระบบเดิม)

**Scenario สาธิต** (ตามลำดับใน [grading/README.md](../grading/README.md#ลำดับการสาธิตที่แนะนำ))

1. เปิด [ตารางสอนของฉัน](../timetable/my-timetable.html) ยื่นคำร้องขอสลับคาบ แล้วกรอกเวลาไม่ว่างวันจันทร์เช้า
2. เปิด "คาบวันนี้" เช็คชื่อ ม.2/1 แล้วดู "ห้องที่ฉันสอน → ค22101 ม.2/1" เห็นนักเรียนเลขที่ 8 เวลาเรียน 71.7% ได้ มส
3. กรอกคะแนน ค22101 ม.2/1 ตั้งโครงสร้าง ค22201 แล้วแก้ ค22101 ม.2/2 ที่ถูกตีกลับตามหมุด และส่งใหม่
4. สลับเป็นมุมมองฝ่ายวิชาการ แล้วอนุมัติ ค22101 ม.2/3 ซึ่งระบบติดป้าย "ตรวจงานตนเอง"

## นักเรียน ม.2/1 — ตัวอย่างในเส้นเรื่อง

นักเรียนไม่ได้ใช้ระบบ แต่เป็นตัวที่ทำให้สาธิตข้ามหน้าได้ต่อเนื่อง ชื่อของนักเรียนสุ่มจาก seed ตอนนี้จึงอ้างด้วยเลขที่

| นักเรียน | สถานการณ์ | เห็นได้ที่ |
|---|---|---|
| ม.2/1 เลขที่ 8 | เวลาเรียน ค22101 71.7% ได้ มส | หน้าห้องที่ฉันสอน, ผลการเรียนใน scores, นักเรียนที่ต้องติดตาม |
| ม.2/1 (คนที่ขาดทั้งวัน) | ขาดทุกคาบในวันเรียนล่าสุดก่อนวันนี้ | ห้องประจำชั้น (ระบบแจ้งเตือนครูสมศรี) |

> ข้อเสนอ: ตั้งชื่อจริงให้นักเรียนสองคนนี้ใน seed เพื่อให้อ้างถึงได้ในเอกสารและตอนนำเสนอ

### คำถามที่ยังเปิดอยู่

- **ปุ่มสลับบทบาทจะสลับคนหรือสลับมุมมอง?** ตอนนี้ปุ่ม "admin" ใน sidebar แสดงชื่อ อ.สุนิสา แต่ในมุมมองฝ่ายวิชาการของ grading แอปยังถือว่าผู้ใช้คือครูสมศรี (`CURRENT_USER_ID = 'u1'`) ป้าย "ตรวจงานตนเอง" จึงขึ้นที่ห้องของครูสมศรี ขณะที่ sidebar บอกว่าเป็น อ.สุนิสา ต้องเลือกระหว่าง
  - ปุ่มสลับมี 3 ตัวเลือก: อ.สุนิสา (admin) · ครูสมศรี (ครู) · ครูสมศรี (ฝ่ายวิชาการ)
  - หรือในมุมมอง admin ของ grading ให้ผู้ใช้เป็น อ.สุนิสา แล้วสาธิตการตรวจงานตนเองด้วยวิธีอื่น
