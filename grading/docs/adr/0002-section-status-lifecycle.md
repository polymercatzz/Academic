# ADR 0002 — วงจรสถานะของห้องเรียนที่สอน: ส่ง → ตรวจ → อนุมัติ / ตีกลับ

- สถานะ: ยอมรับแล้ว (เรื่องคำขอปลดล็อก → [ADR 0005](0005-unlock-request.md))
- วันที่: 2026-09-30

## บริบท
Demo แรกมีสถานะแค่ `draft` กับ `submitted` และปุ่ม “ขอปลดล็อก” จะปลดล็อกทันทีโดยไม่มีใครอนุมัติ
เมื่อมีบทบาทครูฝ่ายวิชาการ การส่งผลการเรียนต้องมีขั้นตรวจสอบ

## การตัดสินใจ
ห้องเรียนที่สอนมีสถานะดังนี้

```
ยังไม่ตั้งโครงสร้าง ──ตั้งโครงสร้าง──▶ กำลังบันทึก ──ครูส่งผล──▶ รอตรวจ
                                        ▲                          │
                                        │ ตีกลับ (พร้อมเหตุผล)       │
                                        └──────────────────────────┤
                                                                   ▼
                                                                อนุมัติแล้ว
```

- **รอตรวจ** — ครูผู้สอนส่งผลการเรียนแล้ว ข้อมูลถูกล็อก และรอฝ่ายวิชาการตรวจ
- **ตีกลับ** — ฝ่ายวิชาการส่งคืนพร้อมเหตุผล สถานะกลับเป็น “กำลังบันทึก” และปลดล็อกให้ครูแก้ไข ครูจะเห็นเหตุผลที่ตีกลับจนกว่าจะส่งใหม่
- **อนุมัติแล้ว** — ฝ่ายวิชาการยืนยันผลการเรียน ข้อมูลถูกล็อก
- การเปลี่ยนสถานะทุกครั้งจะถูกบันทึกในประวัติของห้องเรียนที่สอน

ไม่มีขั้นอนุมัติโดยผู้อำนวยการ (ผู้ใช้เลือกไม่ใช้ในรอบนี้)

## ผลที่ตามมา
- ค่า `state` ในข้อมูลต้องเปลี่ยนจาก `draft | submitted` เป็น 4 สถานะ
- ปุ่ม “ขอปลดล็อก” ต้องไม่ปลดล็อกทันทีอีกต่อไป แต่เป็นการสร้างคำขอให้ฝ่ายวิชาการพิจารณา ([ADR 0005](0005-unlock-request.md))
