# ADR 0011 — เวลาเรียนคำนวณจากการเช็คชื่อรายคาบ และล็อกพร้อมการส่งผลการเรียน

- สถานะ: ยอมรับแล้ว
- วันที่: 2026-10-13

## บริบท
เดิมเวลาเรียน (%) ที่ใช้ตัดสิน มส เป็นตัวเลขที่นำเข้าหรือกรอกเอง (`StudentSubjectResult.attendance_percent`)
เมื่อมีระบบเช็คชื่อรายคาบ ต้องเลือกว่าจะให้สองระบบแยกกัน หรือให้การเช็คชื่อเป็นแหล่งข้อมูลของ มส โดยตรง

## การตัดสินใจ
1. **เวลาเรียน (%) คำนวณจากการเช็คชื่อรายคาบเท่านั้น** = (มา + สาย) ÷ คาบที่เช็คแล้ว ครูไม่กรอกตัวเลขเอง
2. แสดง **ขาดได้อีก** ซึ่งคิดจากจำนวนชั่วโมงตามหลักสูตร เพื่อเตือนล่วงหน้า แต่การตัดสิน มส ใช้ข้อ 1
3. **คาบที่ยังไม่เช็คไม่นับเป็นตัวหาร** และส่งผลการเรียนได้ แต่ระบบเตือนในรายการตรวจสอบก่อนส่ง
4. ครูผู้สอนแก้การเช็คชื่อย้อนหลังได้จนกว่าจะส่งผลการเรียน หลังจากนั้นการเช็คชื่อของห้องเรียนที่สอนนั้น**ล็อกพร้อมคะแนน** ต้องใช้คำขอปลดล็อก ([ADR 0005](0005-unlock-request.md))
5. ~~ข้อยกเว้น: ครูประจำชั้นเปลี่ยน ขาด → ลา ได้แม้ล็อกแล้ว ผ่านการแจ้งลาทั้งวัน~~ **ยกเลิก 2026-10-14:** การแจ้งลาโดยครูประจำชั้นอยู่นอกขอบเขต ลา เป็นสถานะที่ครูผู้สอนเลือกตอนเช็คชื่อเท่านั้น

## ทางเลือกที่ไม่เลือก
- ให้หน้าเช็คชื่อแยกจากระบบคะแนน แล้วนำเข้าตัวเลข % เอง: ข้อมูลซ้ำซ้อน และเลข มส ไม่ตรงกับการเช็คชื่อจริง
- ห้ามส่งผลถ้ายังมีคาบที่ไม่เช็ค: แม่นกว่า แต่ผู้ใช้เลือกให้แค่เตือน

## ผลที่ตามมา
- `StudentSubjectResult.attendance_percent` กลายเป็นค่าที่คำนวณได้ ไม่ใช่ค่าที่กรอก
- ครูที่ไม่เช็คบางคาบจะทำให้เวลาเรียน (%) สูงเกินจริงได้ จึงต้องแสดงจำนวนคาบที่ยังไม่เช็คให้เห็นชัด ทั้งในหน้าเช็คชื่อและตอนส่งผล
- คาบในวันหยุดของโรงเรียน (`db.att.holidays`, UC-25) ไม่อยู่ในคาบที่ต้องเช็ค จึงไม่นับเป็นตัวหาร
- ตารางที่เพิ่มใน ER: `HomeroomTeacher`, `AttendanceSession`, `AttendanceRecord` ([er-data-dictionary ข้อ 8](../er-data-dictionary.md))
