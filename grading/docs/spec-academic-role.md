# Spec — มุมมองครูฝ่ายวิชาการ (Demo รอบที่ 2)

> **สถานะ: สร้างแล้ว 2026-09-30** ส่วนที่ต่างจากแผนเดิมอยู่ในหัวข้อ “ต่างจากแผนเดิม” ด้านล่างสุด

สรุปจากการตัดสินใจใน ADR 0001–0009 ความหมายของคำต่าง ๆ ดูได้ที่ [GLOSSARY](GLOSSARY.md)

## เป้าหมาย
ให้ครูฝ่ายวิชาการเห็นภาพรวมการกรอกคะแนนของทุกห้องเรียนที่สอน แล้วตรวจ อนุมัติ หรือตีกลับได้ โดยไม่แก้คะแนนเอง

## ข้อมูลจำลอง
- ม.1–ม.3 ชั้นละ 3 ห้อง รวม 9 ห้อง
- 8 รายวิชาพื้นฐานต่อชั้น (ท ค ว ส ส-ประวัติ พ ศ ง) รวมประมาณ 72 ห้องเรียนที่สอน
- ครูประมาณ 15 คน ครูสมศรียังสอนห้องเดิม และได้รับบทบาทฝ่ายวิชาการด้วย เพื่อใช้สาธิตการสลับมุมมอง และกรณีตรวจงานตนเอง
- กระจายสถานะให้ครบทุกแบบ: ยังไม่ตั้งโครงสร้าง / กำลังบันทึก (หลายระดับ %) / รอตรวจ (มีและไม่มีข้อสังเกต) / อนุมัติแล้ว / เคยถูกตีกลับ / มีคำขอปลดล็อก
- ตั้งใจใส่ข้อมูลให้เกิดข้อสังเกตครบทั้ง 4 กฎ อย่างน้อยกฎละ 1 ห้อง

## หน้าจอ

### 0. ตัวสลับมุมมอง (หัวเว็บ) — ADR 0003
`มุมมองครูผู้สอน ⇄ มุมมองฝ่ายวิชาการ` เมนูด้านข้างจะเปลี่ยนตามมุมมองที่เลือก

### 1. ภาพรวม (หน้าแรกของฝ่ายวิชาการ)
- การ์ดสรุป: ส่งแล้ว x/72 · รอตรวจ · มีคำขอปลดล็อก · ยังไม่เริ่ม · จำนวนวันที่เหลือก่อนกำหนดส่ง
- **ตาราง ห้อง × รายวิชา** แถวเป็นห้อง ม.1/1 ถึง ม.3/3 คอลัมน์เป็น 8 วิชา
  - แต่ละช่องมีสีตามสถานะ แสดง % ความคืบหน้าหรือไอคอนสถานะ ชื่อย่อครู และจุดแดงถ้ามีข้อสังเกต
  - คลิกช่องเพื่อเปิดหน้าตรวจห้องนั้น
- ตัวกรอง: ระดับชั้น, กลุ่มสาระ, สถานะ, เฉพาะที่มีข้อสังเกต
- แท็บเสริม **รายครู**: ครูแต่ละคน จำนวนห้องที่สอน และจำนวนห้องที่ส่งแล้ว

### 2. กล่องงาน (Inbox)
รายการที่ต้องทำ เรียงจากกำหนดส่งที่ใกล้ที่สุด
- **รอตรวจ** — มีป้าย “ตรวจงานตนเอง” ถ้าใช่ และมี checkbox สำหรับอนุมัติหลายห้องพร้อมกัน (ADR 0008)
- **คำขอปลดล็อก** — แสดงเหตุผลของครู พร้อมปุ่มอนุมัติ / ปฏิเสธ (ADR 0005)

### 3. หน้าตรวจห้องเรียนที่สอน
ใช้แท็บชุดเดียวกับมุมมองครู แต่เป็น**อ่านอย่างเดียวเสมอ** (ADR 0001)
- หัวหน้าแสดงครูผู้สอน สถานะ รอบการตรวจที่เท่าไร และป้ายตามกรณี (ยังไม่ส่ง — ข้อมูลอาจเปลี่ยนแปลง / ตรวจงานตนเอง)
- **โหมดปักหมุด** (เฉพาะห้องที่รอตรวจ) คลิกช่องหรือชื่อนักเรียนเพื่อเพิ่มหมุดพร้อมข้อความ (ADR 0006)
- แถบการตัดสินใจด้านล่าง: `ตีกลับ` (บังคับกรอกเหตุผลรวม และแสดงรายการหมุด) · `อนุมัติ`
- แท็บประวัติแสดงทั้งการแก้คะแนนและทุกรอบการตรวจ

### 4. รายงานภาพรวม (ส่งออก CSV)
- สถานะการส่งของทุกห้อง (ห้อง, วิชา, ครู, สถานะ, วันส่ง, วันอนุมัติ, ผู้อนุมัติ, ตรวจงานตนเอง)
- นักเรียนที่ได้ 0 / ร / มส ของทั้งโรงเรียน

## สิ่งที่ต้องเปลี่ยนในมุมมองครูผู้สอน
- ส่งผลการเรียนแล้วสถานะเป็น **รอตรวจ** (ไม่ใช่ “ส่งแล้ว” เฉย ๆ)
- ถ้าถูกตีกลับ: มีแถบแจ้งเหตุผลที่ด้านบน, หมุดแสดงตรงช่องในตาราง, มีรายการหมุดพร้อมปุ่ม “แก้แล้ว”
- “ขอปลดล็อก” เปลี่ยนเป็นการยื่นคำขอพร้อมเหตุผล และแสดงสถานะว่ากำลังรอพิจารณา
- หน้ากรอกคะแนนมีข้อความว่า “ข้อมูลที่บันทึกแล้ว ฝ่ายวิชาการมองเห็นได้” (ADR 0004)

## โครงข้อมูลที่เพิ่ม (ใน `data.js`)
```js
users:   [{ id, name, roles: ['teacher'] | ['teacher','academic'] }]
section: {
  ...เดิม,
  teacherId,
  state: 'nostructure' | 'draft' | 'pending' | 'approved',
  reviews: [{                         // รอบการตรวจ
    submittedAt, reviewerId, decidedAt,
    decision: 'approved' | 'returned' | null,
    reason,                           // บังคับกรอกเมื่อตีกลับ
    notes: [{ id, sid, field|null, text, resolved }],
  }],
  unlockRequest: { at, reason, status: 'pending'|'approved'|'rejected', decidedBy, decidedAt, rejectReason } | null,
}
```

## ไม่อยู่ในขอบเขตรอบนี้
การแจ้งเตือนครู · ขั้นอนุมัติของผู้อำนวยการ · การปรับเกณฑ์ข้อสังเกตผ่านหน้าจอ · มัธยมปลาย/แผนการเรียน · ระบบล็อกอินจริง

## ต่างจากแผนเดิม (ตอนสร้างจริง)
- ใช้ **9 รายวิชาพื้นฐาน** แทน 8 วิชา เพราะเพิ่ม ว2x103 เทคโนโลยี (วิทยาการคำนวณ) ให้ตรงกับข้อมูลใน Demo แรก ได้ 81 ห้อง และมีรายวิชาเพิ่มเติม 1 ห้อง (ค22201) ซึ่งแสดงแยกใต้ตาราง
- กฎ `MEAN_GAP` เปลี่ยนมาเทียบกับ**ค่ามัธยฐาน** (ดู ADR 0008) เพราะถ้าเทียบกับค่าเฉลี่ย ห้องผิดปกติห้องเดียวทำให้ห้องปกติถูกทักตามไปด้วย
- แถบแจ้งการตีกลับฝั่งครู **ย่อเก็บได้** เพราะตอนมีหมุดหลายอัน แถบจะดันตารางลงไปมาก
- ในข้อมูลจำลองมีครูฝ่ายวิชาการ 2 คน (u1 ครูสมศรี และ u2 หัวหน้าฝ่ายวิชาการ) เพื่อให้มีห้องที่อนุมัติหรือตีกลับโดยคนอื่น แต่ผู้ใช้ใน Demo คือ u1 คนเดียว
- **นำข้อสังเกตอัตโนมัติออก** ตามคำขอของผู้ใช้ ([ADR 0009](adr/0009-remove-automated-observations.md)) ทุกส่วนในสเปกนี้ที่พูดถึงข้อสังเกต จุดแดงในตาราง หรือตัวกรอง “เฉพาะที่มีข้อสังเกต” จึงไม่มีในตัวที่สร้างจริง
